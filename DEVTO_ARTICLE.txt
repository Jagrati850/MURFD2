SECTION 1: INTRODUCTION & THE MISSION
================================================================================

Healthcare accessibility in rural and semi-urban India faces critical structural challenges: long travel distances to district hospitals, shortage of healthcare specialists, and literacy barriers with traditional text-heavy medical mobile applications.

Voice is the most natural and inclusive interface for India. Over 10 days of the Voice for Bharat Challenge 2026, I built the Health Access Voice Agent — an autonomous, privacy-conscious voice AI capable of:
- Understanding symptoms spoken in Indian languages (Hindi, Tamil, Bengali, Marathi, Hinglish).
- Evaluating symptom urgency using deterministic triage rules.
- Locating nearby Primary Health Centres (PHCs) and checking weather/air quality advisories live.
- Remembering returning users across calls using explicit consent.
- Scheduling outbound follow-up calls and medication reminders.
- Escalating red-flag medical emergencies to human ASHA workers and doctors.
- Handing off clinic appointment bookings to a specialist booking agent with an audible voice change!

The secret behind this fluid conversation experience is Murf Falcon — the fastest Text-to-Speech (TTS) API in the industry — delivering instantaneous, human-like voice synthesis with zero latency.


================================================================================
SECTION 2: SYSTEM ARCHITECTURE & TECH STACK
================================================================================

The solution connects real-time audio streaming, LLM reasoning, live domain tools, and persistent SQLite storage.

CORE COMPONENTS BREAKDOWN:

• Speech-to-Text (STT): Deepgram Nova-3 (configured with multilingual support) for automatic Indian language and dialect detection.

• Large Language Model (LLM): Google Gemini 3.5 Flash Lite for rapid tool calling and agentic reasoning.

• Text-to-Speech (TTS): Murf Falcon API (Anisha voice for Main Agent, Pooja voice for Specialist Agent) with sentence tokenization and text pacing for low-latency Indian voice synthesis.

• Real-Time Transport: LiveKit Agents Framework running over WebRTC and WebSockets.

• Database Engine: SQLite operating in WAL (Write-Ahead Logging) mode for high-concurrency memory, escalation, analytics, and appointment tracking.

• Frontend Interface: Next.js 15, TailwindCSS, and a WebGL 3D Shader Dark Orb Visualizer.

SECTION 3: 10-DAY DEVELOPMENT RETROSPECTIVE
================================================================================

MILESTONE 1: STARTER SETUP & MURF FALCON INTEGRATION (DAY 1)
- Integrated Murf Falcon TTS (Anisha voice) into the LiveKit Agents pipeline.
- Established low-latency audio input/output streaming over WebRTC.

MILESTONE 2: PERSONA DESIGN & NATIVE SCRIPT MIRRORING (DAY 2)
- Built an empathetic, calm health assistant persona with strict guardrails (never diagnose, never prescribe medicines).
- Enforced native script rules in system prompts: Hindi is written strictly in Devanagari script (e.g. नमस्ते), Tamil in Tamil script, etc.
- Key Takeaway: Enforcing native script rules ensures Murf Falcon synthesizes authentic Indian regional accents rather than an English-accented pronunciation.

MILESTONE 3: 3D DARK ORB FRONTEND & 5 AGENT STATES (DAY 3)
- Built a WebGL particle visualizer inspired by high-end AI design aesthetics.
- Supported 5 dynamic Agent States: Ready (Click to Start), Connecting, Listening, Speaking, and Ended.
- Included a live transcript switcher allowing users to toggle between 3D particle visualizer and streaming chat text.

MILESTONE 4: PERSISTENT MEMORY WITH CONSENT PROTOCOL (DAY 4)
- Created the user_memory table in SQLite storing preferred name, language, past symptoms, health goals, age band, ongoing conditions, and home district.
- Consent Protocol: The agent strictly asks explicit permission ("May I remember your name and district for next time?") before calling save_user_memory.

MILESTONE 5: LIVE DOMAIN TOOLS & OFFLINE FALLBACKS (DAY 5)
- Implemented 3 domain tools:
  1. find_nearby_health_centre: Live OpenStreetMap Overpass & Nominatim lookup for hospitals and PHCs.
  2. check_local_health_advisory: Live Open-Meteo temperature, heat index, and air quality (AQI) readings.
  3. assess_symptom_urgency: Local deterministic triage sorting symptoms into Red (emergency), Amber (see doctor), or Green (self-care).
- Offline Graceful Degradation: If live APIs time out (8-second limit), the agent speaks a plain fallback message out loud, reads a bundled offline hospital list, and provides official Indian helplines (112, 108).

MILESTONE 6: OUTBOUND CALLS & REMINDERS (DAY 6)
- Implemented tool_trigger_outbound_reminder for scheduling medication reminders and follow-up patient check-ins.

MILESTONE 7: HUMAN EMERGENCY ESCALATION PROTOCOL (DAY 7)
- Red-flag symptoms (chest pain, severe shortness of breath, stroke signs) short-circuit normal conversation.
- The agent delivers emergency warnings, 112 helpline details, asks for permission, and invokes tool_create_human_escalation to save a summary in SQLite for human ASHA workers and doctors.

MILESTONE 8: CALL ANALYTICS DASHBOARD (DAY 8)
- Built an interactive Call Analytics Dashboard (/analytics) powered by SQLite (call_analytics table) and a Next.js API route (/api/analytics).
- Tracks Total Calls, Success Rate %, Failed Calls, Human Escalations, and Live Call Logs.

MILESTONE 9: SPECIALIST AGENT HANDOFF (DAY 9)
- Created a dedicated Clinic & Appointment Specialist (ClinicAppointmentAgent) powered by Murf Falcon (voice: Pooja).
- Implemented transfer_to_clinic_specialist tool on the Main Agent (voice: Anisha).
- Seamless Context Handoff: Uses chat_ctx.copy(exclude_instructions=True) so the specialist inherits all caller details spoken earlier, accompanied by an audible voice switch and a visual DAY 9 HANDOFF card on screen!

MILESTONE 10: MASTER DOCUMENTATION & OPEN SOURCE (DAY 10)
- Released full source code, SQLite database schemas, setup instructions, and architecture documentation on GitHub.

1. PERSISTENT MEMORY SAVE TOOL (DAY 4)

```python
@function_tool()
async def tool_save_user_memory(
    self,
    context: RunContext,
    user_id: str,
    preferred_name: str = "",
    preferred_language: str = "",
    previous_symptoms: str = "",
    health_goals: str = "",
    age_band: str = "",
    ongoing_conditions: str = "",
    home_district: str = "",
) -> dict:
    """Save user information ONLY AFTER the user gives explicit consent."""
    symptoms_list = [s.strip() for s in previous_symptoms.split(",") if s.strip()] if previous_symptoms else None
    goals_list = [g.strip() for g in health_goals.split(",") if g.strip()] if health_goals else None
    conditions_list = [c.strip() for c in ongoing_conditions.split(",") if c.strip()] if ongoing_conditions else None

    return save_user_memory(
        user_id=user_id,
        preferred_name=preferred_name or None,
        preferred_language=preferred_language or None,
        previous_symptoms=symptoms_list,
        health_goals=goals_list,
        age_band=age_band or None,
        ongoing_conditions=conditions_list,
        home_district=home_district or None,
    )
```

2. SPECIALIST AGENT HANDOFF TOOL (DAY 9)

```python
@function_tool()
async def transfer_to_clinic_specialist(self, context: RunContext) -> tuple[Agent, str]:
    """Transfer user to the Clinic & Appointment Specialist (voice: Pooja) for doctor slot bookings."""
    logger.info("Performing agent handoff -> ClinicAppointmentAgent")
    await self._publish_to_ui("handoff", {
        "agent_name": "Clinic & Appointment Specialist",
        "voice": "Pooja (Murf Falcon)",
        "specialist_role": "Doctor Consultations & Slot Booking",
        "data_freshness": "live",
        "status": "transferred",
        "message": "Conversation transferred to Clinic & Appointment Specialist (Voice: Pooja)"
    })
    specialist = ClinicAppointmentAgent(
        chat_ctx=self.chat_ctx.copy(exclude_instructions=True)
    )
    return specialist, "Transferring you to our Clinic and Appointment Specialist now."
```

3. SPECIALIST AGENT DEFINITION & BOOKING TOOL (DAY 9)

```python
class ClinicAppointmentAgent(Agent):
    def __init__(self, chat_ctx: ChatContext | None = None) -> None:
        super().__init__(
            instructions=SPECIALIST_PROMPT,
            chat_ctx=chat_ctx,
            tts=murf.TTS(
                voice="Pooja",
                style="Conversation",
                tokenizer=tokenize.basic.SentenceTokenizer(min_sentence_len=2),
                text_pacing=True,
            ),
        )

    async def on_enter(self) -> None:
        await self.session.generate_reply(
            instructions="Introduce yourself warmly as the Clinic & Appointment Specialist (voice: Pooja). Offer to help book their doctor slot or check clinic timings."
        )

    @function_tool()
    async def tool_book_clinic_appointment(
        self,
        context: RunContext,
        user_name: str = "Caller",
        facility_name: str = "Primary Health Centre",
        preferred_date: str = "Tomorrow",
        time_slot: str = "10:00 AM",
        contact_number: str = "Provided on Call",
    ) -> dict:
        """Book a doctor consultation slot at a clinic or Primary Health Centre (PHC)."""
        user_id = self._get_user_id()
        return book_clinic_appointment(
            user_id=user_id,
            user_name=user_name,
            facility_name=facility_name,
            preferred_date=preferred_date,
            time_slot=time_slot,
            contact_number=contact_number,
        )
```


================================================================================
SECTION 5: CHALLENGES & ENGINEERING FIXES
================================================================================

KEY TECHNICAL CHALLENGE 1: ELIMINATING STARTUP LATENCY
- Problem: Heavy turn-detector imports were triggering PyTorch initialization delays (~50 seconds) before registering the agent worker with LiveKit Cloud.
- Fix: Optimized plugin imports in agent.py, reducing worker registration speed from 56 seconds down to under 1 second!

KEY TECHNICAL CHALLENGE 2: NATIVE SCRIPT PRONUNCIATION
- Problem: Standard LLMs reply in Romanized Hindi ("namaste main aapki madad kar sakta hoon"), causing TTS engines to speak with an English accent.
- Fix: System prompt rules strictly enforce writing in native scripts (Devanagari Hindi: नमस्ते). Murf Falcon synthesizes native script text with flawless Indian pronunciation.

KEY TECHNICAL CHALLENGE 3: RURAL NETWORK TIMEOUTS
- Problem: Live API lookups fail or time out on weak mobile connections.
- Fix: Built graceful degradation — 8-second timeouts trigger an audible fallback explanation, read local district data, and provide 112/108 helplines.

SECTION 6: HOW TO RUN & DEPLOY LOCALLY
================================================================================

STEP 1: CLONE THE REPOSITORY
```bash
git clone https://github.com/Jagrati850/MURFD2.git
cd MURFD2
```

STEP 2: CONFIGURE ENVIRONMENT VARIABLES
Create a .env.local file in both backend and frontend directories:

Backend (.env.local):
```env
LIVEKIT_URL=wss://your-project.livekit.cloud
LIVEKIT_API_KEY=your_livekit_api_key
LIVEKIT_API_SECRET=your_livekit_api_secret
MURF_API_KEY=your_murf_api_key
DEEPGRAM_API_KEY=your_deepgram_api_key
GOOGLE_API_KEY=your_gemini_api_key
```

Frontend (.env.local):
```env
LIVEKIT_URL=wss://your-project.livekit.cloud
LIVEKIT_API_KEY=your_livekit_api_key
LIVEKIT_API_SECRET=your_livekit_api_secret
AGENT_NAME=health-agent
```

STEP 3: START BACKEND & FRONTEND
Run using the PowerShell launcher:
```powershell
.\start_app.ps1
```

Or run manually in two terminals:
Terminal 1 (Backend): cd backend && uv run python src/agent.py dev
Terminal 2 (Frontend): cd frontend && pnpm dev

Open http://localhost:3000 in your browser to test live voice interaction!
