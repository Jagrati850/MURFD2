Section 1: Introduction & The Mission

Healthcare accessibility in rural and semi-urban India faces critical structural challenges: long travel distances to district hospitals, shortage of healthcare specialists, and literacy barriers with traditional text-heavy medical mobile applications.

Voice is the most natural and inclusive medium for India. Over 10 days of the Voice for Bharat Challenge 2026, I built the Health Access Voice Agent — an autonomous, privacy-conscious voice AI capable of:

  • Understanding symptoms spoken in Indian languages (Hindi, Tamil, Bengali, Marathi, Hinglish).
  • Evaluating symptom urgency using deterministic triage rules.
  • Locating nearby Primary Health Centres (PHCs) and checking weather/air quality advisories live.
  • Remembering returning users across calls using explicit consent.
  • Scheduling outbound follow-up calls and medication reminders.
  • Escalating red-flag medical emergencies to human ASHA workers and doctors.
  • Handing off clinic appointment bookings to a specialist booking agent with an audible voice change!

The secret behind this fluid conversation experience is Murf Falcon — the fastest Text-to-Speech API in the industry — delivering instantaneous, human-like voice synthesis with zero latency.

Section 2: System Architecture & Tech Stack

The solution connects real-time audio streaming, LLM reasoning, live domain tools, and persistent SQLite storage.

Core Technologies

  • Speech-to-Text (STT): Deepgram Nova-3 (multilingual support) for automatic Indian language and dialect detection.
  • Large Language Model (LLM): Google Gemini 3.5 Flash Lite for rapid tool calling and agentic reasoning.
  • Text-to-Speech (TTS): Murf Falcon API (Anisha voice for Main Agent, Pooja voice for Specialist Agent) with sentence tokenization and text pacing.
  • Real-Time Transport: LiveKit Agents Framework running over WebRTC and WebSockets.
  • Database Engine: SQLite operating in WAL (Write-Ahead Logging) mode for high-concurrency memory, escalation, analytics, and appointment tracking.
  • Frontend Interface: Next.js 15, TailwindCSS, and a WebGL 3D Shader Dark Orb Visualizer.

Section 4: Key Feature Implementations & Code Deep-Dives

1. Persistent Memory with Consent Protocol (Day 4)

To personalize care without compromising privacy, the agent uses an SQLite user_memory table backed by a strict consent rule: it asks explicit permission before executing memory saves.

@function_tool()
async def tool_save_user_memory(
    self,
    context: RunContext,
    user_id: str,
    preferred_name: str = "",
    preferred_language: str = "",
    previous_symptoms: str = "",
    health_goals: str = "",
    age_band: str = "",
    ongoing_conditions: str = "",
    home_district: str = "",
) -> dict:
    """Save user information ONLY AFTER the user gives explicit consent."""
    symptoms_list = [s.strip() for s in previous_symptoms.split(",") if s.strip()] if previous_symptoms else None
    goals_list = [g.strip() for g in health_goals.split(",") if g.strip()] if health_goals else None
    conditions_list = [c.strip() for c in ongoing_conditions.split(",") if c.strip()] if ongoing_conditions else None

    return save_user_memory(
        user_id=user_id,
        preferred_name=preferred_name or None,
        preferred_language=preferred_language or None,
        previous_symptoms=symptoms_list,
        health_goals=goals_list,
        age_band=age_band or None,
        ongoing_conditions=conditions_list,
        home_district=home_district or None,
    )

When a caller asks to book a clinic appointment, the Main Agent (voice: Anisha) invokes transfer_to_clinic_specialist. The conversation transfers seamlessly to the ClinicAppointmentAgent (voice: Pooja) while preserving caller context.

async def transfer_to_clinic_specialist(self, context: RunContext) -> tuple[Agent, str]:
    """Transfer user to the Clinic & Appointment Specialist (voice: Pooja) for doctor slot bookings."""
    logger.info("Performing agent handoff -> ClinicAppointmentAgent")
    await self._publish_to_ui("handoff", {
        "agent_name": "Clinic & Appointment Specialist",
        "voice": "Pooja (Murf Falcon)",
        "specialist_role": "Doctor Consultations & Slot Booking",
        "data_freshness": "live",
        "status": "transferred",
        "message": "Conversation transferred to Clinic & Appointment Specialist (Voice: Pooja)"
    })
    specialist = ClinicAppointmentAgent(
        chat_ctx=self.chat_ctx.copy(exclude_instructions=True)
    )
    return specialist, "Transferring you to our Clinic and Appointment Specialist now."

Section 6: Database Schema Architecture (SQLite WAL Mode)

The system stores state across 4 dedicated tables in an SQLite database using WAL (Write-Ahead Logging) mode:

  • user_memory: Stores user_id, preferred_name, preferred_language, previous_symptoms, health_goals, age_band, ongoing_conditions, home_district, last_conversation_time.
  • human_escalations: Stores escalation_id, user_id, user_name, urgency, reason, summary, user_language, preferred_contact, status.
  • call_analytics: Stores call_id, user_id, user_name, outcome, triage_level, duration_seconds, summary, timestamp.
  • clinic_appointments: Stores appointment_id, user_id, user_name, facility_name, preferred_date, Process time_slot, contact_number, status.

Section 7: Technical Challenges & Solutions

1. Eliminating Process Startup Delay (From 56s down to <1s)
Problem: Pre-importing heavy turn-detector packages in agent.py triggered PyTorch checks, causing a 56-second process initialization lag.
Solution: Refactored plugin imports in agent.py, enabling the agent worker to register with LiveKit Cloud in 0.5 seconds.

2. Native Script Accent Mirroring
Problem: Standard LLMs generate Romanized Hindi ("namaste main aapki madad kar sakta hoon"), causing TTS engines to speak with an English accent.
Solution: Enforced strict Devanagari script rules in system prompts (e.g. नमस्ते), enabling Murf Falcon to synthesize authentic Indian regional pronunciation.

3. Rural Network Resilience
Problem: Live API lookups fail on weak mobile network connections.
Solution: Built 8-second timeouts that trigger audible fallback explanations out loud while reading local district data and providing official Indian helplines (112, 108).

Section 8: How to Run & Deploy Locally

Follow these steps to run the complete voice application locally:

1. Clone the Repository

git clone https://github.com/Jagrati850/MURFD2.git
cd MURFD2

2. Configure Environment Variables

Create a .env.local file in both backend and frontend directories:

Backend (backend/.env.local):

LIVEKIT_URL=wss://your-project.livekit.cloud
LIVEKIT_API_KEY=your_livekit_api_key
LIVEKIT_API_SECRET=your_livekit_api_secret
MURF_API_KEY=your_murf_api_key
DEEPGRAM_API_KEY=your_deepgram_api_key
GOOGLE_API_KEY=your_gemini_api_key

Frontend (frontend/.env.local):

LIVEKIT_URL=wss://your-project.livekit.cloud
LIVEKIT_API_KEY=your_livekit_api_key
LIVEKIT_API_SECRET=your_livekit_api_secret
AGENT_NAME=health-agent

3. Start Backend & Frontend

Run using the PowerShell launcher:

.\start_app.ps1

Or run manually in two terminals:

# Terminal 1 (Backend)
cd backend
uv run python src/agent.py dev

# Terminal 2 (Frontend)
cd frontend
pnpm dev

Open http://localhost:3000 in your browser to test live voice interaction!
